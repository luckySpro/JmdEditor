# 在宝塔面板部署 JmdEditor 导出服务

这个包是微信小程序和网页版要用的后端服务（从链接导入、导出 Word/PDF）。它是一个独立的程序，不需要安装 Rust、Docker 或其他依赖，适用于 64 位 x86 Linux（CentOS 7+、Ubuntu、Debian、Alibaba Cloud Linux 等）。

包里的文件：

| 文件 | 作用 |
| --- | --- |
| `jmd-server` | 服务程序 |
| `start.sh` | 启动脚本，宝塔里填它 |
| `jmd-server.env.example` | 配置模板，第一次启动时自动复制成 `jmd-server.env` |
| `fonts/` | PDF 导出用的中日文字体 |
| `web/` | 浏览器版编辑器（可选） |
| `jmd-server.service` | 不用宝塔时的 systemd 配置（可选） |

## 1. 上传并解压

1. 宝塔「文件」进入 `/www/wwwroot/`，上传 `jmd-server-linux-x64.tar.gz`。
2. 右键「解压」，得到 `/www/wwwroot/jmd-server/` 目录。
3. 宝塔「终端」执行一次，让 www 用户能运行和写配置：

```bash
chown -R www:www /www/wwwroot/jmd-server
chmod +x /www/wwwroot/jmd-server/start.sh /www/wwwroot/jmd-server/jmd-server
```

## 2. 启动服务（二选一）

**方式一：进程守护管理器（推荐）**

1. 「软件商店」搜索并安装「进程守护管理器」（Supervisor）。
2. 打开它，点「添加守护进程」：
   - 名称：`jmd-server`
   - 启动用户：`www`
   - 运行目录：`/www/wwwroot/jmd-server`
   - 启动命令：`/www/wwwroot/jmd-server/start.sh`
   - 进程数量：1
3. 保存后状态显示「运行中」即可。服务器重启后会自动拉起。

**方式二：网站 → Go 项目 / 其他项目**

宝塔版本里有「Go 项目」或「其他项目」时，也可以在那里添加：

- 项目执行文件：`/www/wwwroot/jmd-server/jmd-server`
- 执行命令：`/www/wwwroot/jmd-server/start.sh`
- 项目端口：`8787`（不要勾选放行端口）
- 运行用户：`www`

## 3. 绑定域名和 HTTPS

小程序只能访问 HTTPS 域名，所以要用宝塔的 Nginx 反向代理。

1. 「网站」→「添加站点」，填域名（如 `md-api.example.com`），PHP 选「纯静态」，不建数据库。
2. 站点「设置」→「SSL」→ Let's Encrypt 申请证书，并打开「强制 HTTPS」。
3. 站点「设置」→「反向代理」→「添加反向代理」：
   - 目标 URL：`http://127.0.0.1:8787`
   - 发送域名：`$host`
4. 浏览器打开 `https://你的域名/api/health`，看到 `ok` 就部署成功了。

服务只监听 `127.0.0.1:8787`，外网只能通过上面的 HTTPS 域名访问，不需要在宝塔「安全」里放行 8787 端口。

## 4. 配置小程序

1. `apps/miniprogram/config.js` 里把 `API_BASE` 改成 `https://你的域名`。
2. 微信公众平台「开发管理 → 开发设置 → 服务器域名」，把同一个地址加到「request 合法域名」。

## 修改配置

编辑 `/www/wwwroot/jmd-server/jmd-server.env`，然后在进程守护管理器（或 Go 项目）里点「重启」。常用项：

| 配置 | 说明 |
| --- | --- |
| `JMD_ADDR` | 监听地址，默认 `127.0.0.1:8787` |
| `JMD_TRUST_PROXY` | 在宝塔 Nginx 后面时保持 `1` |
| `JMD_MAX_CONCURRENT` | 同时导出的数量，内存小的机器可设为 `1` 或 `2` |
| `JMD_EXPORT_TIMEOUT_SECS` | 单次导出超时秒数 |
| `JMD_RATE_PER_MIN` | 每个 IP 每分钟请求上限，`0` 为不限 |
| `JMD_STATIC` | 留空则不提供网页版编辑器 |

## 升级到新版本

1. 在进程守护管理器里「停止」jmd-server。
2. 上传新版 `jmd-server-linux-x64.tar.gz` 到 `/www/wwwroot/`，解压并覆盖。你的 `jmd-server.env` 不在包里，不会被覆盖。
3. 重新执行第 1 步里的 `chown` 和 `chmod`，再「启动」。

## 排查问题

- 看日志：进程守护管理器里点「日志」，或在终端运行 `cd /www/wwwroot/jmd-server && ./start.sh` 直接看输出（Ctrl+C 退出）。
- `Permission denied`：没执行第 1 步的 `chown`/`chmod`。
- `Address already in use`：8787 被占用，改 `JMD_ADDR` 的端口，同时改反向代理的目标 URL。
- 导出的 PDF 中文是方块：`fonts/` 目录丢失或 `JMD_FONT_DIRS` 路径不对。
- 从 GitHub 链接导入失败：服务器访问不了 GitHub，国内服务器较常见。
